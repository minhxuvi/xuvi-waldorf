## Goal
Build a Vietnamese-first, teacher-facing web product for Waldorf-Inspired education in Vietnam per [00_master_prompt.md](/Users/moc/Projects/xuvi-waldorf/specs/00_master_prompt.md): **XuVi Story** (upload → story map → illustration → record → feedback) plus **six on-demand documents** (Overall program, Detailed program by grade/age, MOET alignment matrix, Academic-year plan, Timetable/weekly plan, Teaching journal + assessment records). Children are not app users; telling stays screen-free. Source corpora are [01-Waldorf-co-dien-lop-1-12.md](/Users/moc/Projects/xuvi-waldorf/references/01-Waldorf-co-dien-lop-1-12.md), [02-Waldorf-Cambridge-lop-1-12.md](/Users/moc/Projects/xuvi-waldorf/references/02-Waldorf-Cambridge-lop-1-12.md), [03-Nha-Thuan-Nhien-mam-non-lop-12.md](/Users/moc/Projects/xuvi-waldorf/references/03-Nha-Thuan-Nhien-mam-non-lop-12.md), [Việt Huyền Sử Ký.md](</Users/moc/Projects/xuvi-waldorf/references/Việt Huyền Sử Ký.md>), [xuvistory.md](/Users/moc/Projects/xuvi-waldorf/references/xuvistory.md), and the 1,555-page TT32 PDF in `references/`. Current tree is clean-slate (only spec + references; prior code removed in `ba35a9c clean to build again`), so this is a fresh build, not an extension.

## Success Criteria
1. Teacher can sign up, own a family/child profile (no child login), upload a story (DOC/DOCX/PDF/HTML/MD/TXT), edit a story map, generate or upload per-scene images behind a review gate, record/upload a retelling, correct the transcript, and receive fixed-form feedback (strengths + missing/altered details + one next step, no score).
2. All six documents generate from one shared content model, are parent-editable, lockable, and export to print/PDF with provenance labels and a no-legal-recognition disclaimer.
3. Document 3 shows only verbatim MOET bullets with labelled product-generated internal IDs; allocated hours never render as MOET-prescribed; no score/ranking/certification claim appears anywhere.
4. Every AI call sits behind a provider interface with a provisioned non-Meta fallback; Vietnam reachability and Vietnamese quality are proven by a probe report before the primary provider is locked.

## Approach
**Assumptions (reversible, stated not asked):** single-family v1 with a path to multi-family; Vietnamese UI/documents first, English for stories/prompts second; responsive web (no native apps); the 08:00–15:00 Mon–Fri timetable from the master prompt is the default template; 36 teaching + 4 festival weeks is a *family-chosen* rhythm, not a hard-coded Waldorf fact, because the three corpora band time incompatibly (block-weeks vs periods/week vs clock minutes).

**Recommended stack:** TypeScript web monolith (UI + API in one codebase), PostgreSQL, object storage for audio/images, background job queue for every AI call, server-rendered PDF. AI never invents hours, MOET text, or alignment degrees — deterministic rendering owns Document 3, Document 5, and all arithmetic; the LLM only drafts narrative prose for Documents 1/2/4/6 and proposes story maps.

**Meta product verdicts (provisional — every "use" is gated on the Step 0 probe, because Meta Model API availability and Vietnamese benchmarks from Vietnam are unverified):**

| Capability | Primary to probe | Fallback | Verdict rationale |
|---|---|---|---|
| Story segmentation, doc drafting, feedback | Spark Standard tier (`muse-spark-1.3`), Wonder (`muse-wonder-1.0`) as quality escalation | One non-Meta LLM with Vietnamese support | Standard tier only — Contributor tier trains on inputs and is forbidden for child-adjacent data |
| Illustration | Meta Image (`muse-image-1.0`) | One SDXL/Flux/OpenAI-image-class provider | Prompt in English; mandatory parent cultural/age review gate |
| Speech-to-text | Meta Voice Transcribe (`muse-voice-transcribe-1.0`, Vietnamese-validated) | Whisper-class STT with word timestamps | Turn-level timestamps alone cannot judge pacing/pauses — supplement with word timestamps + energy/VAD |
| SAM 3.1, Spark Open, Glimmer, Baseten, Modal, Fireworks | — | — | **Not used in v1** — no mask-requiring flow exists; self-hosting only if a later probe creates the need |

**Shared content model:** `Family (teacher) → ChildProfile (no login) → Program → GradeProgram → AlignmentRow → YearPlan → TimetableSlot → JournalEntry/PeriodicReport`, plus XuVi entities `Story, Audience, StoryMap, SceneImage, Attempt` (no score column by construction). Hours stored natively per unit (`official_hours` vs `allocated_hours_product`, never silently converted); every corpus/MOET-derived value carries a provenance label; corpus conflicts (MN banding, exam-vs-Waldorf precedence, foreign-language timing) surface as labelled family choices, never silent merges.

**Non-goals for v1:** native mobile apps, child-facing UI, child accounts, multi-school tenancy, offline-first sync, efficacy/score claims, legal filing/certification claims.

## Steps
1. **Pre-flight probe (gate, no product code).** Verify tooling (Node/pnpm, Python/`uv`, Postgres, Docker if needed), DB + object-storage read/write/delete, and one minimal live call per AI capability on primary *and* fallback (segment a synthetic Vietnamese folktale paragraph; one watercolor prompt; transcribe a short adult-recorded Vietnamese clip). Record Vietnam reachability, latency, and Standard-tier data terms in the progress log. Failures route that capability to its fallback before Step 2.
2. **Scaffold + quality gates.** Monolith skeleton (app, API routes, job queue, fail-fast env loading), Postgres + storage clients, health endpoint, `dev/build/test/lint/typecheck/test:e2e` scripts, `.env.example`, Vietnamese-first i18n scaffolding.
3. **Shared content model + invariants.** Migrations for the model above; invariant tests reject silent hour conversion, unconfirmed alignment rows in exports, and any score field.
4. **Teacher auth, privacy, audit.** Single-family auth, private-by-default, per-story/per-account export + delete, per-action AI disclosure (which service receives what, before it is sent), audit log of every outbound AI payload. Document 6 gets strictest retention.
5. **MOET dataset ingestion.** Extract TT32 from the local PDF into one row per verbatim *yêu cầu cần đạt* bullet (subject, grade, cấp, strand, paired *nội dung*, source locator); official hours only at tiết/năm/subject/grade; internal IDs labelled product-generated; TT32 currency caveat stored as dataset metadata.
6. **Corpus defaults + Documents 1/2/4.** Seed configurable defaults from the three corpora with per-value provenance/caveats; LLM drafts narrative prose, parent edits and locks; flagged/`pending_confirmation` corpus rows stay excluded until the content owner approves them row-by-row.
7. **Deterministic Documents 3 + 5.** Document 3 renders only parent-confirmed `AlignmentRow`s with allocated time, VI.2 verification methods, and the product-taxonomy degree set (*đầy đủ / một phần / deferred + roadmap / tiếp cận khác / chưa bao phủ*) labelled as product taxonomy. Document 5 renders the 08:00–15:00 grid distinguishing instructional time from routines, planned vs actual duration. No LLM touches either.
8. **Document 6 journal + reports.** Continuous journal entries (date, content, attendance, assessment, assignments, artifacts, progress notes) rolling up to periodic narrative reports with teacher sign-off; fields minimal and family-configurable.
9. **PDF/print export for all six.** Server-rendered PDF, prototyping the two hard layouts first (wide Document 3 matrix, Document 5 grid); every export carries the disclaimer and provenance; no score or recognition claim.
10. **XuVi core: upload, audience, story map.** Library with in-app text review + source/usage-rights metadata; audience settings (age, language, context, practice goal) with age gating; AI-proposed, parent-edited story map (chapters → scenes/characters/essential details); [Việt Huyền Sử Ký.md](</Users/moc/Projects/xuvi-waldorf/references/Việt Huyền Sử Ký.md>) mid-band chapters (4–8k chars) as the stress fixture, never ingested as one story.
11. **XuVi visuals, practice, recording.** Per-scene illustration (wet-on-wet watercolor / wax crayon / colored pencil) or upload behind the mandatory review gate (unapproved images provably unusable in practice); practice with fading prompts; recording/upload with replay, STT behind the provider interface, transcript correction, attempt labelling (with/without prompts, assistance tracked separately), delivery features from audio (pauses/pacing).
12. **XuVi feedback, history, evaluation harness.** Fixed-form comparative feedback vs the selected story version + map, distinguishing omissions from intentional adaptations; labelled practice history with optional seven-day rhythm; the two-story blinded comparison from [xuvistory.md](/Users/moc/Projects/xuvi-waldorf/references/xuvistory.md) as an offline, file-only evaluation — never surfaced as an efficacy claim.
13. **Quotas, cost, hardening.** Per-family AI/storage quotas (calls × unit price formulas, no absolute totals until vendor pricing is final), job concurrency limits, retention policy, full-suite run from a clean clone, disclaimer/provenance sweep. Execution loop: tasks run sequentially; each ends with its verification passing, a progress-log entry, and one Git commit; three consecutive failed fixes on one error stops execution for reviewer input; tests are never edited to force a pass.

## Validation Plan
- **Step 1:** probe script exits 0 with its report in `specs/04_progress_log.md`; each capability's primary provider is named from *probe evidence*, not assumption.
- **Per-task:** the task's named tests run unmodified, full scope (e.g. content-model invariant negatives, `uv run --with pypdf` ingestion `--check` with verbatim diffs on sampled PDF pages, golden-file renders for Document 3/5, PDF snapshot comparison, `xuvi-story-map` / `xuvi-feedback` suites including a proof that no score can be stored or returned).
- **End-to-end:** `pnpm build && pnpm lint && pnpm typecheck && pnpm test && pnpm test:e2e` from a clean clone, plus E2E flows for privacy export/delete, doc generate-edit-lock, story upload-to-map, and record-correct-retry.
- **Highest-risk validation:** Step 1 probes (Meta reachability + Vietnamese segmentation/feedback/STT quality) — if Meta is unreachable from Vietnam, fallbacks become primary by configuration, not architecture change.

## Risks / Open Questions
- **Risks:** TT32 currency not verifiable against an official source (carry the caveat in UI/exports; never assert it); homeschooling has no official recognition in Vietnam (product is planning/evidence tooling only); NTN is the least-clean corpus (10 ERROR / 39 REVIEW audit flags) yet the only one covering mầm non; STT Vietnamese WER unpublished (transcript correction is the mitigation); audio storage dominates cost at scale (quotas + retention from v1).
- **Open questions** (defaults in brackets apply if unanswered): MN default presentation [no silent default — explicit family choice]; may flagged corpus rows seed content [research-only until row-by-row approval]; foreign-language timing [family selector]; exam-vs-Waldorf precedence per grade [family-chosen, neither pre-selected]; story age-gating criteria [drafted in Step 10, shown to reviewer before the test-story set locks]; v1 grade span [full mầm non–lớp 12, MN gated on the first choice].
